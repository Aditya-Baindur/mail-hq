# Security and operations

Mailbox deletion is a dashboard-only operation protected by Cloudflare Access, same-origin checks, and an exact address confirmation. The confirmation covers stored messages, drafts, attachments, and connected app access. Literal routing rules are inspected before removal: only the selected address’s exact rule targeting this Worker can be deleted. Protected addresses, forwarding rules, other Workers, and catch-all rules are preserved. Managed catch-all domains require no token to delete an individual mailbox.

Deletion pauses the mailbox before cleanup, blocking delivery, sending, mail-app sessions, OAuth, and manual agent tokens. Routing permission failures keep stored mail intact. Private R2 objects are removed in bounded batches from that mailbox’s mail, upload, and IMAP prefixes; database records and the search index are then removed transactionally. A durable cleanup marker permits retry after interruption without needing the provisioning token again. Database guards reject writes already in flight, and those handlers discard their uploaded objects. Deletion leaves an audit event and never runs merely by deploying this feature.

Mail HQ serves personal email. Keep the dashboard behind Cloudflare Access and the R2 bucket private. Its Worker validates the Access application JWT and rejects mutations from another origin. Access policies determine dashboard users; there is no second hardcoded email allowlist.

MCP uses the Cloudflare Workers OAuth provider with PKCE S256, resource-bound tokens, dynamic client registration and client ID metadata documents. The authorization page uses the existing signed Access session. Every consent requires mailbox selection and explicit permissions; a browser-bound cookie and an atomic D1 claim make consent specific to that browser, user and approval. Client-supplied names and callback destinations are shown and escaped. No approval is inferred from a previous connection.

OAuth access tokens expire in one hour; connections expire after 30 days. The provider stores encrypted grant properties and token identifiers in private KV. Every MCP call and token exchange additionally checks D1 for revocation, connection expiry and mailbox status. This prevents stale KV access after dashboard revocation. D1 stores only connection IDs and permission metadata, never OAuth credentials. Connections are managed by their signed-in owner under Agents. Existing manual mailbox tokens remain random, hashed at rest, scoped, expiring and revocable. Never publish credentials or put access/refresh tokens in URL query strings. Read access does not authorize mailbox mutations.

Keep `global_fetch_strictly_public` enabled for safe public client-metadata fetching. Discovery, token and registration endpoints stay outside interactive Access; only the consent page belongs on the protected dashboard origin. OAuth responses are not cached, query strings are redacted from Worker request logs, and consent pages disable referrer transmission and framing. See [OAuth operations](mcp-oauth.md).

The optional Cloudflare provisioning credential is AES-GCM encrypted in R2. Keep `CONFIG_ENCRYPTION_KEY` stable and backed up privately. Restrict the token to intended zones and permissions. No normal app endpoint overwrites existing MX or email routing rules.

Inbound HTML is sanitized with DOMPurify before it runs in a sandboxed frame. Scripts, forms, embedded documents, and automatic redirects are removed; a restrictive CSP also blocks script execution, forms, and remote fonts. The frame permits same-origin access only so the parent can measure its content without enabling scripts. External HTTP(S) images load by default and can be disabled per message; loading them can contact sender tracking servers. Images and links suppress referrers, and links open separately with no opener. Inline image attachments are fetched through the authenticated attachment endpoint. Received mail is untrusted input, including when returned by MCP to an agent. Review agent permissions before allowing it to send.

Retries of a send must reuse its idempotency key. A network failure after submission can make the outcome uncertain; do not automatically resend. A provider-accepted message may still bounce or be filtered into spam.

Retain database and object-storage backups together. Message metadata refers to bodies and attachments by object key. Rolling back Worker code does not roll back D1 or R2. Trash is reversible; there is no automatic permanent-deletion job.

Keep real email samples, deployment account records, private keys, environment files, generated deployment bundles, and test-recipient logs out of Git. Local operator records belong in ignored `.local/`.
